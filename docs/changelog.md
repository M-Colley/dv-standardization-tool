### [2026-11-04] Code review and cross-study relations

A review of the whole pipeline (harmonization, LLM fallback and benchmark, cross-study analyses) found the defects below; each is fixed and has a regression test in `tests/test_review_fixes.py`.

**Harmonization**

- **Columns combined by the sign of their correlation.** When several columns map to one DV, the batch averaged them into a composite and first flipped any column that correlated negatively with an anchor column. Columns that measure different things (a baseline next to later ratings, an LLM guess next to curated items) were thus sign-flipped and averaged. In AV Acceptance VR the three curated perceived-safety items were flipped to match LLM-mapped anxiety items. Items are now never flipped on the evidence of the data: a group with a negative correlation is left uncomposed (`skip_negative_item_correlation`), reverse keying comes only from a mapping file, and LLM-mapped columns are never combined with deterministically mapped ones (`skip_mixed_provenance`). Bookkeeping columns (`meta_*`) are not combined.
- **Uncomposed duplicates.** When columns of one DV stayed uncomposed, the analysis used whichever came first and ignored the rest. It now averages them per row (repeated measurements of the DV).
- **An optimizer's inverted copy of an answer.** eHMI Optimization stores each rating twice: the participant's answer (QuestionnaireResponses) and the Bayesian optimizer's objective (ObservationsPerEvaluation), where mental demand is inverted (11 − answer for 720 of 740 evaluations). Both were mapped to `mental_demand`, so participant means of the two cancelled out. The new manifest `table_options` key `drop_columns` drops the optimizer's copy; participant ids for the questionnaire files come from their folder names (`participant_from_file` in `study_designs.yaml`).
- **Raw NASA-TLX on the wrong scale.** The registry scored the raw TLX on its items' coding, so studies with 0–20 subscales got 0–20 totals that were pooled as `TLX_SCORE` (0–100) next to 0–100 totals. Subscales are now put on 0–100 before averaging (`centering: proportion`).
- **Recording scales inside the DV's range.** The analysis rescales a DV only when its values leave the DV's range, so a narrower scale inside it went unnoticed. New mapping block `scale_conversions` (linear, declared per column, validated, listed in `-quality.json` and the data package). Fixed: WoZ Adaptation's NASA-TLX on 0–10 (now 0–20); Curved Dragging's error rate as a proportion mapped to a percentage DV (now its percent column); In-car VR's TLX sum (0–120) mapped to `TLX_SCORE` (now left out; the score comes from the subscales).
- **A baseline rating as the study's FMS.** FOV Snap-Turn's eight FMS time points were mapped to `fms_score` but could not be averaged (one exists only for withdrawers), so the minute-0 rating stood for the study. The session average ADS is now the score.
- **Schema:** reverse-keyed SUS and Van der Laan items are `lower_is_better` (they were `higher_is_better`, so contrasts called a gain in usefulness unfavourable); `dwell_time` is no longer also an alias of `retention_time`; `total time` is no longer an alias of `pedestrian_crossing_time` (in eHMI for All it is the whole trial, averaged with the time on the intersection). Schema 3.2.
- **Perceived safety scored from its items** (`perceived_safety_items` in the registry, as in the BVI study's analysis script), so studies that report only the four items contribute the scale.
- **Header matching:** a header with a unit in parentheses ("Completion time (ms)") is no longer matched by its cleaned name to a DV in another unit; plain headers ("Mental Demand") now get the cleaned-alias lookup.
- **Single-file conversion:** the automatic long-to-wide reshape no longer pivots a table whose other columns vary within a participant (it kept one DV of a wide within-subject table, or averaged two measures).

**Provenance and the LLM fallback**

- **The benchmark showed the model the answer.** The prompt lists the first three aliases of each candidate DV, and in the leave-alias-out benchmark the held-out alias was among them for 86 of 265 E1 and 216 of 300 E2 items. Aliases equal to the queried column are now left out (no effect in the pipeline, where such a column is mapped before the LLM is asked). All benchmark numbers below are from the rerun.
- **E1 skipped unit conversions** the pipeline applies before the LLM step, so its range check saw milliseconds where the pipeline sees seconds (27 crossing-time items).
- **LLM-derived values in "LLM-excluded" outputs.** Items of LLM-built composites were read as the scale's real items (`perceived_safety__item_2` as `perceived_safety_item_02`) without provenance, and questionnaire scores computed from LLM-mapped items counted as non-LLM. Composite items are no longer read as scale items, and scores inherit the most cautious provenance of their items.
- **Study mappings labelled as the shared schema.** Every mapping file under `schemas/` counted as `schema`, so curated mappings could not be told from the shared vocabulary. Only the `standard_*_mapping.yaml` files count as `schema` now.
- **`meta_view.csv`** marks LLM rows for review (`review_flag`, `mapping_confidence: llm_unreviewed`); they were `high`.
- **Plausibility rules 1.3:** the 15% tolerance widens only the canonical range (on the alternative scales it accepted accelerations of −2.6..1.8 g as a −2..2 Van der Laan item); the LimeSurvey timing rule needs the question code itself (`reactionTime` next to `reactionCorrect` is a DV).

**Analyses**

- **Participant-level unit.** Aggregation used the first ID-like column, which dropped every survey DV of eHMI for All (its log files' `user_id` came first) and used survey response ids elsewhere. It now uses the participant columns declared in `study_designs.yaml`, now declared for all 23 studies (`participant_scope: file` where ids restart per file). Contrasts and invariance fits get row-level data even with `--repeated-measures`.
- **Subgroups** counted an item and its own scale score as independent effects; items next to their score are dropped and each study counts once per cluster.
- **Meta-regression** was fixed-effect: its slope test ignored residual heterogeneity (p < .05 for 60% of null slopes at τ = 0.5, k = 6). It is now a random-effects meta-regression with the Knapp-Hartung test (`statsmodels` WLS; intercept-only it equals the DL estimate with the HKSJ interval).
- **Leave-one-out** rows show `k_remaining`, `pooling_method` and the HKSJ interval (at k = 3 the remaining two studies are pooled with fixed effects).
- **Causal discovery ignored `--exclude-llm-deduced`.** LiNGAM, its bootstrap and the PC skeleton always ran on LLM-mapped columns, and the teaser figure's DAG came from In-car VR with its ride *relaxation* rating as TiA trust and a motion-sickness maximum as STS-AD trust. With the flag they now drop LLM-deduced columns; the DAG now rests on Running into Traffic's deterministic columns (n = 270).

**New: cross-study relations** (`opendv/analysis/construct_relations.py`, `docs/cross_study_insights.md`). Correlations between harmonized constructs are pooled across studies (between persons and within persons; REML, HKSJ, prediction intervals, BH q), and every column is traced to the step that mapped it: identical names, shared schema, curated mapping or LLM.
- **Ladder:** no pair of constructs is measured in three studies under the same names, or with the shared schema and header matching alone; 29 with the curated mappings and 54 with the LLM (between persons).
- **Finding:** within persons, higher mental demand goes with lower perceived safety in all four studies that measured both repeatedly (r = −0.44, HKSJ [−0.72, −0.05], q = .04); between persons the relation is uncertain (r = −0.27, five studies). The NASA-TLX subscales covary within persons in every study, with *performance* the weakest link.
- **LLM:** reaches 21 studies instead of 16; its new cross-construct findings rest partly on wrong mappings (a ride's relaxation rating as trust) and still look homogeneous.
- **Replay** (`--llm-replay-items`): with the LLM's leave-alias-out answers in place of the curated mappings, 46 of 161 curated DV columns keep their DV and none of the 16 within-person findings survives (69 and one with `dense_h`); relations both versions pool agree closely (median |Δr| 0.06–0.09).

**LLM benchmark rerun** (three shortlists, every curated column asked about with `--max-per-source 1000`; numbers on the default 40-per-source sample): `definition` 41% of 255 DV columns correct (45% before the leak fix), precision 31% (37%), E2 accuracy 60% (68%). `dense_h` and `mixed_h` 49% and 48% (p = 0.009, 0.008), but not better on the 12 added studies (p = 0.34, 0.27), so `definition` stays the default. The plausibility check now loses 1 of 106 correct mappings (a sampled file whose answers are all 1). The pre-registered confirmatory runs are not rerun: the leak touches 1 of their 168 items.

**Regenerated outputs** (`analyses/output_python_full/`, `output_multiverse/`, `figures_chi/`, new `output_relations/`):
- `TLX_SCORE` (LLM-excluded) is 34.7 on 0–100 (5.95 before); `mental_demand` 8.12 (7.39), with WoZ's subscales on 0–20 and eHMI Optimization's answers instead of the optimizer's copy.
- `perceived_safety` is pooled over four studies (two), scored from the items of BVI and eHMI for All; its four items now rest on the two studies that report them (seven before: five through composite item columns that had no provenance).
- Contrasts come from 14 studies (7). eHMI vs. none on perceived safety becomes estimable (+1.02 SD, two studies).
- Invariance: perceived safety misfits configurally (RMSEA 0.21); scales whose studies all repeat answers are fitted participant-clustered again.
- ROADS' SUS score leaves the LLM-excluded pooling: provenance is per study and DV, and the LLM mapped a "reality" item of another ROADS file to SUS item 1.

### [2026-11-04]

- **Decimal commas.** A semicolon- or tab-separated file whose numbers use decimal commas (`24,825`, common in German or French spreadsheet exports) is now read with pandas' `decimal=","` (`opendv.data_loaders._detect_decimal`, also used by the UI uploader). The loader decides per file, and only when the sample has decimal-comma numbers and no decimal-point ones, because pandas would turn `1.5` into text under `decimal=","`.
  - Before this, numeric coercion kept only the integer-valued cells of such columns, so summaries came from a biased subset. The confirmatory VR study's trial times were summarized from 259 of 8,640 trials (mean 29.3 s, mostly 30-s timeouts) instead of all of them (9.3 s).
  - In the development studies the change reaches ROADS' and osf_cwd6h's log files: 1,779 files, no column losing numeric parsing. In the regenerated catalog only osf_cwd6h's 20 eye-tracking and sensor channels change (216 logs). They were summarized from 2.3 million of their 30.7 million cells, and 3,672 of the 4,318 summaries were empty. No DV changes.
- **`True`/`False` columns** (as text, or as booleans in a column with gaps, which pandas keeps as object) are recoded to 1/0 by `recode_survey_answer_codes` (kind `true_false`). The VR study's per-trial `Success` now reaches the LLM.
- **Failed LLM calls are no longer abstentions.**
  - **Before:** a generation call that raised (e.g. CUDA out of memory while another job used the GPU) was logged at DEBUG and left the column unmapped, exactly like an abstention. In one development batch this silently removed all 32 FACT-AV LLM mappings.
  - **Now:** failures are logged as warnings and collected (`llm_utils.generation_errors`), and an out-of-memory error is retried once after freeing cached GPU memory. The batch reports the count in `run_summary.json` (`llm_generation_errors`). The benchmark harness flags each affected item (`llm_error`) and exits with an error.
  - **Earlier results:** no committed run shows the fast unanswered calls a failure leaves.
- **Frozen manuscript context.** The prompt's repository context includes manuscript text fetched from the DOI's landing page, which can differ between requests: one confirmatory rerun got another PDF excerpt for Hi-Audio and changed 41 `mixed_h` answers.
  - **Caching:** fetched text is now kept in a `joblib.Memory` cache under the source cache (`llm_context/`), shared by the batch and the benchmark harness. A failed fetch is retried on the next run rather than frozen.
  - **Fingerprints:** each source's context fingerprint is recorded (`llm_context_sha256` in `run_summary.json`; `context_sha256` in the harness summary).
  - **Earlier results:** the three pre-registered confirmatory runs logged the same PDF context.
- **Confirmatory post hoc rerun** (not pre-registered), with the three shortlists run one after another on the shared context and no failed call: `definition` 64 correct (64 vs. 55 before, p = 0.004), `dense_h` 54, `mixed_h` 57, all because the VR `Success` column is now mapped correctly; otherwise identical to the 2026-11-03 rerun. With header matching first: 106 / 93 / 99 correct, precision 59.9% for `definition`.
- **Development rerun.** The LLM batch, the analyses and the LLM benchmark of the three shortlists were rerun one after another on the shared context, with no failed call.
  - Every benchmark item (470 per shortlist) is identical to the 2026-11-03 run, so the published development numbers stand.
  - The LLM catalog differs only in the osf_cwd6h sensor channels above.
  - Pooled estimates, multiverse ranges and figures are unchanged.
- **12 open-data studies added to the development set** (23 in all; `docs/open_data_candidates.md`). Seven are from HCI fields outside automotive research. Each file is pinned by size and the host's checksum in `analyses/development_sources/sources.yaml` and downloaded with `python -m opendv.analysis.confirmatory fetch --sources analyses/development_sources/sources.yaml --data-dir data/raw/development`. Their curated mappings were committed before any LLM run on these studies. One candidate (`acoustic_touch_blind_plosone23`) was left out because Dryad refused automated downloads.
- **Reading files as declared.** Needed for the added studies:
  - **Manifest `table_options`** (per file path or glob): sheet, header row, and the pivot of a long table to one column per value. The pivot uses `DataFrame.pivot`, so duplicate rows fail instead of being averaged.
  - **Mapping `missing_values`:** declared codes (98/99 "no answer") become missing before any other recoding.
  - **Mapping `unit_conversions`:** time DVs recorded in another unit than the schema states are converted, with factors from pandas' `Timedelta` units. One added study records crossing initiation times in ms, which were otherwise pooled with seconds.
  - **Encoding detection:** a sample that decodes as UTF-8 is read as UTF-8. charset-normalizer had labelled a UTF-8 sample cut mid-character as cp932.
  - Both mapping blocks are checked by the validator and listed in `-quality.json` and the data package.
- **Scale detection picked 0–20 for any off-range scale.** When a column's values left its DV's canonical range, `_detect_scale_range` took the first listed alternative scale that held the data, and 0–20 was listed first. 1–5 Van der Laan answers (canonical −2..2) were thus read as a 0–20 scale and became −1.7 with a standard deviation of 0.1. It now takes the narrowest common scale that holds every value.
- **Van der Laan scores of ROADS and eHMI for All had the wrong sign.** Both store the items as −2..2 with +2 at each item's first word (useful, pleasant, bad, …), while the instrument registry's −2..2 coding has −2 there. Their usefulness and satisfying scores therefore correlated −0.72 to −0.83 with SUS from the same answers (+0.42 and +0.51 in the added FIDO2 study). The eHMI-for-All analysis script also scores a high `aoa1` as useful; the ROADS script applies the 1–5 formula to its −2..2 answers. Both studies now have a mapping file that declares the nine items reverse-keyed. Benchmark items are unaffected: the reversed columns span −2..2 either way.
- **Invariance fits failed with between-subject studies.** lavaan refuses participant clusters when a study has one observation per participant. Every scale shared with an added study therefore failed to fit, and the error was reported as level "none", like a real misfit. Such scales are now fitted without clusters (robust MLR, noted in each row's `warning`), and a model that cannot be fitted is reported as `not_fitted`.
- **Analyses with 23 studies** (`analyses/output_python_full/`, `output_multiverse/`, `figures_chi/`):
  - **Coverage:** 49 DVs are pooled over at least two studies without LLM-deduced rows (34 before), 35 over at least three (6); `mental_demand` over 7.
  - **Changed by the fixes above:** Van der Laan usefulness is +0.96 (was −0.63); Running into Traffic's perceived safety is +0.85 on −3..3 (was −1.93), and 11 other study means in five original studies moved off the 0–20 reading.
  - **Invariance:** none of the six testable scales reaches scalar invariance. Van der Laan *satisfying* reaches metric and *usefulness* configural (scalar and metric with the original two studies); SUS, NASA-TLX and both UEQ-S scales misfit at the configural level.
  - **Multiverse:** `mental_demand` stays robust (7.07–7.63). Some specifications include LLM-deduced rows, and in those `task_completion_time` reaches 1,287: the LLM mapped an added study's decision time in ms, which its curated mapping leaves out.
- **LLM benchmark per subset** (`evaluate_llm_mapping.py --subset NAME=SOURCES_YAML`): E1 is also summarized for the listed sources and for the rest (`e1_by_subset`). On the 12 added studies, which no method was tuned on, `definition` maps 68 of 164 DV columns correctly (precision 29%) and `dense_h` and `mixed_h` 70 each (paired p = 0.85 and 0.81). The original 11 studies' items are identical to the previous run. See `docs/research_agenda.md` §2.4 for the error patterns.

### [2026-11-03]

- **Survey answer codes recoded before screening.** `recode_survey_answer_codes` (`opendv/value_labels.py`) turns array-question answer codes into numbers before the non-numeric screen:
  - LimeSurvey sub-questions (`Q[SQ001]`, `Q_sq001`) holding `A1`/`A01` codes;
  - yes/no answers (`Y`/`N`, `Yes`/`No`, `Ja`/`Nein`) become 1/0.

  Each recoding is recorded in the quality JSON (`survey_answer_codes_recoded`) and the data package. In the 11 development studies only six non-DV columns change: osf_cwd6h's four yes/no car-use questions and two constant "Y" flags (3D display `general`, FACT-AV `videoInfo`). No DV and no pooled estimate changes.
- **Header matching against instrument item wording.** `opendv/header_matching.py` handles blocks of question-text headers (for example "How mentally demanding was the task? (0 = Low, 100 = High)"):
  - it embeds the cleaned headers and the registered items' wording (`Item.wording` in `schemas/instruments.yaml`, for SUS and NASA-TLX) with `multilingual-e5-small`;
  - it assigns them one-to-one (Hungarian assignment);
  - it accepts a block only with at least 4 matches in a compact window and a similarity of at least 0.80.

  It runs before the LLM. Its mappings get their own provenance (`header_match`, priority between repository and LLM mappings) and appear in the review queue. `--no-header-matching` turns it off. It maps nothing new in the development studies, whose headers are short codes.
- **Keying check.** `opendv.instruments.keying_check` flags registered items whose loading on the first principal component of the item correlations runs against their key (key × loading ≤ −0.3, at least 20 complete rows and 3 items), in the manner of `psych::check.keys`. Warnings go to the log and `run_summary.json` (`instrument_keying_warnings`); nothing is reversed automatically. Run on the state before the 2026-10-26 fix, it finds Running into Traffic's reversed TLX performance item (−0.59, n = 288). It finds nothing in the current development studies.
- **Indicator rule in the plausibility check.** Yes/no recoding first let the LLM map osf_cwd6h's yes/no demographics to `dali_total` and `tam_perceived_ease_of_use`, and the all-"Y" `general` flag to `trust_rating`, because 0–1 fits inside most response scales. A 0/1 column is now never accepted for a DV whose `measurement.category` is Likert or Score (`binary_for_rating_scale`; these five proposals are rejected). Binary and count DVs (`task_success`, `number_of_collisions`) are not affected. Plausibility rules are now version 1.2. LLM benchmark on the development studies: the rule also rejects Scrolling-in-the-Deep's `At_Home` indicator (proposed as `psychological_reactance`). Curated non-DV columns mapped to a DV drop from 35% to 30% and precision rises from 59% to 60% (52 of 87; `dense_h` 76%, `mixed_h` 78%). Correct mappings and E2 are unchanged. Regenerated LLM batch: `meta_view.csv` differs from the previous run only in the six recoded non-DV columns, which stay unmapped. Pooled estimates, multiverse ranges and the figures are unchanged.
- **Post hoc rerun of the confirmatory test.** This is not pre-registered: two of the fixes were designed after seeing those data. The rerun uses `analyses/confirmatory/posthoc.sh`, the new `python -m opendv.analysis.confirmatory posthoc`, and outputs in `analyses/confirmatory/posthoc/`. Of the 168 DV columns:
  - `definition` maps 63 correctly (55 before; 8 Hoffman trust items now reach the LLM; p = 0.008);
  - `dense_h` and `mixed_h` are unchanged at 53 and 56, so `definition` stays the default;
  - header matching assigns 45 question-text columns, all correct and with no non-DV column. Header matching first and the LLM for the rest gives 105 correct (precision 60%, was 36%).

  The keying check flags AgencyUX's TLX performance item. The study's codebook confirms the reversal ("How successful were you…? low–high"). It also flags Hi-Audio's physical demand at n = 22, probably not a keying error. New studies are needed to confirm the gains (`docs/confirmatory_shortlist_results.md`).

### [2026-10-25]

- **`opendv` package (3.1.0).** The code moved from the generic top-level packages `scripts/`, `analyses/` and `ui/` into one installable package: `opendv` (pipeline), `opendv.sources`, `opendv.analysis` (with the lavaan script) and `opendv.ui`. Schemas ship as package data (`opendv.schemas`) and are found through `opendv._paths.SCHEMAS_DIR` both installed and in a checkout. The old module paths are aliases of the same module objects in a checkout, so existing imports, mocks and commands keep working; only `opendv` is installed. New public API (`opendv.standardize`, `run_batch`, `analyze`, `review_queue`, `score`, `load_plugins`), `opendv ui` and `opendv plugins` commands, an `opendv-review` console script, and entry-point plugin groups `opendv.sources`, `opendv.loaders` and `opendv.instruments`. Batch and analysis outputs are identical to 3.0 on the 11-study benchmark (1,764 standardized tables, `meta_view.csv`, 31 analysis tables). CI installs the wheel and imports it outside the checkout.

- **Documented condition codes for ROADS and Psych-Conflict.** Their numeric condition codes are now declared in `schemas/study_designs.yaml` as coded in each repository's own R analysis script: ROADS interaction concept (Trajectory / Path planning / Waypoint) x number of requests (One-Four); Psych-Conflict persuasion strategy (12 levels, Baseline reference) and mechanism (Cognitive / Social / Politeness / Emotional). Both are within-subject, study-specific factors, so they add within-study contrasts (735 contrast effects in 7 studies, was 345 in 5). E.g. more requests raise ROADS workload by 0.86-1.36 SD; socially pressuring strategies lower Psych-Conflict acceptance by 0.43 SD. Integer condition codes read as floats (`3.0`) now match integer levels (`3`).

### [2026-10-17]

- **Parallel batch standardization.** `run_batch_standardization.py --workers N` (also `run_catalog_meta_analysis.py`) processes datasets in worker processes. Outputs match a sequential run file for file; LLM deduction stays in the main process and runs in file order. Mappings are now built once per (schema family, repository mapping) rather than once per file, numeric columns skip a redundant `to_numeric` pass during summarization, and delimited files are opened twice instead of three times.
- **Faster analysis loading.** `multi_study_analysis.py` reads files in a thread pool and skips files that have no canonical DV column (`load_studies(..., skip_files_without_dvs=True)`, on by default in both CLIs). Studies whose files are all skipped are kept as empty frames, so study counts and coverage percentages do not change. Schema YAML is parsed once with libyaml's C loader.
- **Trim-and-fill fixed.** `trim_and_fill` previously mirrored every study on one side of the pooled mean instead of estimating the number of missing studies. It now implements Duval & Tweedie's iterative L0/R0 estimator, matching `metafor::trimfill` (k0, side, adjusted estimate and SE) on two published datasets (`tests/test_meta_analysis_reference.py`). It uses the main analysis model (`--estimator`, default DL), picks the side automatically, and writes a row for every evaluated DV, including those with `k_imputed = 0`.
- **REML scoring step corrected.** The Fisher information in `_estimate_tau2_reml` was missing the `(Σw²/Σw)²` term. The converged estimate was already right, but convergence is now reliable. Estimates agree with direct maximisation of the restricted likelihood to within 1e-6.
- **Composite index no longer imputes empty rows.** Rows with none of the shared DVs observed (e.g. telemetry rows of a study whose questionnaire lives in another file) used to be median-imputed into all-zero z-rows. That inflated `n`, shrank SDs, and dominated the PCA. Such rows are now dropped before imputation.
- **Causal analysis.** Construct → item relationships now also come from the DV schema (`<construct>_item_NN` ids or an explicit `subitem_of`), so item → scale edges cannot enter the LiNGAM DAG. Bootstrap edge stability (via `lingam.DirectLiNGAM.bootstrap`, seeded) and the PC skeleton now run on the same observations as the reported DAG; before, they silently returned nothing whenever DVs only partly overlapped across studies.
- **Extension points.** Dataset-type profiles drive schema-family selection, LLM eligibility and item composition. Source types are registered with `register_source_type`. HTTP 502/503/504 outages are reported as `temporarily_unavailable`.
- **LLM plausibility check.** New `scripts/llm_plausibility.py` with `schemas/llm_plausibility_rules.yaml` (v1.1). It keeps demographic, ID, seed, timestamp, survey-timing, coordinate, condition, ranking and non-numeric columns away from the LLM, and rejects suggestions whose values fit no plausible scale. Rejections are logged to `llm_rejected_suggestions.json`; `--no-llm-plausibility-check` turns the check off for ablation.
- **LLM mapping benchmark.** `analyses/evaluate_llm_mapping.py` provides a leave-alias-out evaluation against curated mappings (E1: real dataset columns; E2: held-out schema aliases), with Wilson CIs. Results are in `analyses/output_llm_evaluation/`.
- **Small-sample intervals and a multiverse.** `meta_analysis_summary.csv` gains Hartung-Knapp-Sidik-Jonkman columns (`hksj_se`, `hksj_ci95_low`, `hksj_ci95_high`), validated against metafor. `analyses/multiverse_analysis.py` writes 32-specification robustness summaries and specification curves.
- **Dependencies updated to the newest releases.** Includes pandas 3.0.6, numpy 2.5.4, scikit-learn 1.9.1, matplotlib 3.11.2, transformers 5.20.1, torch 2.14.1, openai 3.33, sentence-transformers 6.1, plotly 7.1, streamlit 1.66, pytest 9.1 and ruff 0.17 (`torch` is now declared in the LLM extra). scipy stays at 1.16.x and lingam at 1.12.2: lingam 1.13.0 pins `scipy<=1.13.1`, which cannot be installed with numpy ≥ 2.3, and its dependency pygam requires `scipy<1.17`. CI now tests Python 3.12 and 3.14 with `actions/checkout@v7` / `setup-python@v7`; Python 3.15 is left out until PyYAML ships 3.15 wheels. The LLM prototype notebook now uses the current OpenAI client API.

The figure script derives every caption number from the run, renders alternative runs via `OPENDV_ANALYSIS_DIR` / `OPENDV_BATCH_DIR` / `OPENDV_FIGURES_DIR`, labels the three newer studies, and no longer overlaps the Fig. 2 caption with DV labels.

Previously eHMI-for-All and ROADS silently lost every negative AOA answer (about 30% of cells), biasing AOA means upward. Derived AOA usefulness/satisfying scores now use each study's coding midpoint (0 for −2…+2, 3 for 1…5) instead of a hard-coded 3.
